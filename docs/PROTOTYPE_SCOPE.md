# SandPlanet Prototype Scope

> 목적: 21일 전체 게임을 구현하기 전에 핵심 루프가 실제로 재미와 선택 압박을 만드는지 확인한다.
> 이 문서의 범위는 **프로토타입용 가안**이며, 정식 시나리오 분량을 확정하는 문서가 아니다.

## 기술 방향 — 확정
- 엔진은 **Unity 3D**를 사용한다.
- 현재 프로젝트 버전은 Unity 6000.4.1f1 / Universal 3D 기반이다.
- 이 프로토타입은 버리는 웹 샌드박스가 아니라 **최종 게임으로 확장 가능한 기반 프로토타입**으로 제작한다.
- 시스템과 콘텐츠 데이터는 가능한 한 분리해, 이후 21일 콘텐츠를 추가할 때 핵심 코드를 다시 작성하지 않도록 한다.
- 3D는 직접 캐릭터를 조작하는 월드가 아니라 **디오라마형 허브/공간 선택 화면**으로 우선 사용한다.

## 현재 확정된 화면 문법
### 1~2주차
`3D 행성 허브 → 장소 화면 → 2D 인카운터 → 결과 → 장소/행성 복귀`

- 행성 허브에는 수송선 / 묘지 / 거주지 / 오아시스 등 3D 랜드마크가 배치된다.
- 행성 화면 자체에서 바로 실행 가능한 인카운터가 존재할 수 있다.
- 장소를 클릭하면 해당 장소의 2D 화면으로 전환되고, 여러 인카운터 카드 중 하나를 고른다.
- 인카운터는 장소 이미지 / 캐릭터 포트레이트 / 텍스트 / 선택지를 중심으로 표현한다.
- 행성 허브의 `! / … / 인물` 표시는 각각 긴급·행성 인카운터 / 장소 인카운터 / NPC 콘텐츠 존재를 알리는 UI 후보다.

### 수송선
- 수송선은 일반 장소 인카운터 외에 별도의 **정비도**를 가진다.
- 시스템적으로 선행/단계 구조를 가질 수 있지만, 플레이어에게는 스킬트리보다 **실제 수송선의 부위를 수리하는 화면**으로 보여야 한다.
- 시설 상태는 현재 `기능 불능 → 응급 복구 → 정상 작동 → 완전 복구/보강`의 0~3단계 가안을 사용한다.

### 3주차
- 모래폭풍이 시작된 뒤에는 행성 허브 대신 **3D 수송선 내부 허브**를 메인 공간으로 사용하는 방향을 채택한다.
- 같은 화면 문법을 유지하되, 플레이 질문이 `어디를 방문할까?`에서 `어디를 먼저 살릴까?`로 바뀌는 것이 목표다.
- 1~2주차에 수리한 상태가 3주차 수송선 내부 공간과 생존 난이도에 반영되는 구조를 지향한다.

## Phase 0 — 짧은 시스템 샌드박스
정식 1~3일차를 그대로 재현하기보다, 세 번의 하루 루프 안에서 핵심 시스템을 빠르게 검증한다. 화면상 게임 기간과 시스템 구조는 최종 게임의 `DAY n / 21` 체계를 그대로 사용한다.

### Prototype 0.1 — 완료
핵심 시스템이 실제 Unity에서 한 사이클로 작동하는지 검증했다.

검증 완료 항목:
- DAY / 시간 루프
- 의지력 소비 / 낮잠 / 수면 회복
- 시작 스탯 배분
- 개인 / 대인 / 기술 경향성 성장
- NPC 호감도 0~5 샘플
- Soft / Hard Requirement 샘플
- 퀘스트 기반 설득 샘플
- 기술자 동료 조건
- 수송선 방호 0~3단계 수리 샘플
- 3D 랜드마크 클릭

### Prototype 0.2 — 현재
**게임 화면 구조와 정보 흐름을 검증한다.** 콘텐츠 양을 늘리는 단계가 아니다.

반드시 포함:
1. 3D 행성 허브의 수송선 / 묘지 / 거주지 / 오아시스 클릭.
2. 랜드마크 Hover 피드백.
3. 행성 허브의 `! / … / 인물` 상태 표시.
4. 장소 진입 시 허브 위 단순 패널이 아니라 **별도 장소 화면으로 명확하게 전환**.
5. 장소당 2×3 형태의 인카운터 카드 그리드 샘플.
6. 인카운터 진입 시 **2D 비주얼 영역 + 텍스트/선택지 영역**으로 화면 전환.
7. 시간 / 의지 / Soft / Hard 조건 표시 및 기존 0.1 규칙 유지.
8. 수송선 장소에서 별도 **수송선 정비도** 진입.
9. 정비도에는 코어 / 추진 / 거주 / 방호 위치를 배치하되, 0.2에서는 방호만 실제로 작동하고 나머지는 PLACEHOLDER로 둔다.
10. 아트는 사용하지 않고 색면/그레이박스로 화면 구조만 판단한다.

0.2 성공 기준:
- `3D 행성 → 장소 → 2D 인카운터`의 단계가 플레이어에게 명확하게 구분되는가?
- 장소 화면의 인카운터 카드 구조가 콘텐츠를 고르는 화면으로 이해되는가?
- 행성의 상태 아이콘이 어디를 방문할지 판단하는 데 도움이 되는가?
- 수송선 정비 화면이 스킬트리보다는 `배를 수리한다`는 느낌의 기반으로 읽히는가?
- 실제 아트를 넣기 전에 UI 구조에서 수정해야 할 문제가 무엇인지 발견할 수 있는가?

## 현재 기본 규칙
1. **하루 시간 루프**
   - 기본 08:00~22:00.
   - 행동마다 시간 소비.
   - 하루 종료 및 다음날 진행.

2. **의지력**
   - 기본 최대 5.
   - 행동에서 의지 소비.
   - 낮잠: 2시간 / +1 의지.
   - 수면 후 +2 의지.

3. **시작 스탯 배분**
   - 개인 / 대인 / 기술에 총 6포인트 배분.
   - 각 스탯 상한 20.

4. **경향성 성장**
   - 행동마다 개인/대인/기술 태그 기록.
   - 하루 종료 시 가장 많이 사용한 분야 +1.

5. **NPC 호감도**
   - 0~5 단계.
   - 호감도와 설득은 별도 시스템이다.

6. **퀘스트 기반 설득**
   - 설득 게이지를 사용하지 않는다.
   - 한 NPC에게 몇 차례 설득 기회가 있고 그중 한 번의 조건부 선택지에 성공하면 설득 성공으로 처리하는 방향이다.
   - 개인/대인/기술 부족분 중 일부는 의지력으로 보완할 수 있는 Soft Requirement가 될 수 있다.
   - 동료 / 정보 / 퀘스트 상태 / 시설 상태 등 Hard Requirement는 의지로 우회할 수 없다.

7. **수송선 시설**
   - 현재 0~3단계 상태 구조를 시험한다.
   - 정식 시설 구성과 세부 수리 공식은 아직 TBD다.

## Phase 0에서 하지 않는 것
- 21일 전체 시나리오 작성.
- 모든 NPC 퀘스트 구현.
- 전체 스킬트리 구현.
- 완성형 엔딩 구현.
- 3주차 모래폭풍 전체 시뮬레이션.
- 아트/연출 완성.
- 대규모 랜덤 인카운터 풀 제작.
- 아직 결정되지 않은 세부 수치나 NPC 설정을 AI가 임의로 정식 사양화.
