# SandPlanet Prototype Scope

> 목적: 21일 전체 게임을 구현하기 전에 핵심 루프가 실제로 재미와 선택 압박을 만드는지 확인한다.
> 이 문서의 범위는 **프로토타입용 가안**이며, 정식 시나리오 분량을 확정하는 문서가 아니다.

## Phase 0 — 3일 시스템 샌드박스
정식 1~3일차를 그대로 재현하기보다, 세 번의 하루 루프 안에서 핵심 시스템을 빠르게 검증한다.

### 반드시 포함
1. **하루 시간 루프**
   - 기본 08:00~22:00.
   - 행동마다 시간 소비.
   - 하루 종료 및 다음날 진행.

2. **의지력**
   - 최대 5.
   - 행동에서 의지 소비.
   - 낮잠: 2시간 / +1 의지.
   - 수면 후 +2 의지.

3. **시작 스탯 배분**
   - 개인 / 대인 / 기술에 총 6포인트 배분.
   - 각 스탯 최대 20 구조는 유지하되 프로토타입에서는 낮은 범위만 사용.

4. **경향성 성장**
   - 행동마다 개인/대인/기술 태그 기록.
   - 하루 종료 시 가장 많이 사용한 분야 +1.
   - 어떤 행동 때문에 성장했는지 결과 화면에서 확인 가능.

5. **NPC 호감도**
   - 0~5 단계.
   - 최소 2명의 기존 NPC를 사용해 관계 행동을 검증.
   - 대사는 플레이스홀더여도 되지만, 관계 변화 원인은 UI에서 확인 가능해야 한다.

6. **퀘스트 기반 설득 1건**
   - 설득 게이지 없이 특정 조건 선택지로 해결.
   - 조건 예: 호감도 / 정보 플래그 / 대인 수치 중 2개 이상 조합.
   - 스탯 부족을 의지로 보충하는 Soft Requirement 예시 1건 포함.
   - Hard Requirement는 의지로 우회할 수 없음을 검증.

7. **수송선 시설 1종**
   - 0~3 단계 상태 구조를 시험.
   - 조사 → 필요한 조건 확인 → 수리/작업 지시 → 상태 변화의 한 사이클을 구현.
   - 기술자 동료 또는 임시 전문가 플래그가 필요한 작업 예시 포함.

8. **스킬/퍽 최소 샘플**
   - 전체 스킬트리를 구현하지 않는다.
   - 개인/대인/기술 각 1~2개만 구현해 데이터 구조와 효과 적용 방식을 검증.
   - 개인 예시: `강한 육체` 또는 `아침형 인간`.

9. **디버그/상태 UI**
   플레이 테스트 중 최소한 다음 값을 항상 확인할 수 있어야 한다.
   - 현재 Day / 시간
   - 현재/최대 의지
   - 개인 / 대인 / 기술
   - 오늘의 경향성 누적치
   - NPC 호감도 및 주요 플래그
   - 수송선 시설 상태

## Phase 0에서 하지 않는 것
- 21일 전체 시나리오 작성.
- 모든 NPC 퀘스트 구현.
- 전체 스킬트리 구현.
- 완성형 엔딩 구현.
- 3주차 모래폭풍 전체 시뮬레이션.
- 아트/연출 완성.
- 대규모 랜덤 인카운터 풀 제작.

## 성공 기준
프로토타입 플레이 후 다음 질문에 답할 수 있으면 성공이다.
1. 시간과 의지 중 무엇을 아껴야 할지 실제 고민이 생기는가?
2. 개인/대인/기술 빌드 차이가 같은 문제의 해결 방식에 차이를 만드는가?
3. 호감도와 설득이 분리되어 있어도 플레이어가 관계를 쌓을 이유가 있는가?
4. 의지력으로 부족한 스탯을 보완하는 선택이 의미 있는 리스크가 되는가?
5. 수송선 수리와 NPC 동료화가 하나의 루프로 연결되는가?
6. 하루 종료의 경향성 성장이 '내가 한 행동이 제이를 만든다'는 느낌을 주는가?

## 구현 순서 권장
1. 상태 데이터 모델
2. 시간/의지 루프
3. 행동 실행 시스템
4. 경향성/하루 종료 성장
5. NPC 호감도 및 플래그
6. 설득 조건 시스템
7. 수송선 시설 상태와 작업
8. 샘플 퍽
9. 디버그 UI 및 플레이 테스트

## 기술 스택
아직 확정하지 않는다. 엔진/프레임워크 선택은 별도 결정으로 남긴다.
